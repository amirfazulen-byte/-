# «Коррекция»: консьерж-версия бота

Telegram-бот для пилота с 10–15 мастерами (план проверки в [korrekciya-validation-kit.md](korrekciya-validation-kit.md)).

## Что умеет

**Мастер** пишет боту одной фразой («Аня, пт 14:00, коррекция») или **пересылает сообщение клиентки** («давайте в пятницу в 14»). Во втором случае имя берётся из пересылки, а «завтра» считается от дня, когда клиентка написала. В `/stats` видно, какая доля записей добавлена пересылкой: это главный показатель того, приживается ли ввод записей.
- Бот создаёт запись и даёт ссылку, которую мастер один раз отправляет клиентке.
- За 24 часа до визита клиентка получает кнопки «Приду / Перенести / Отменить». Мастер узнаёт о каждом ответе.
- Если клиентка не ответила в течение 4 часов (или позже чем за 3 часа до визита), бот предупреждает мастера.
- Если клиентка не в Telegram, бот отправляет SMS (если оно настроено), а иначе просит мастера напомнить ей вручную.
- Через 2 часа после визита бот спрашивает мастера, пришла ли клиентка. Из этих ответов складывается **честная статистика неявок**, на которой строится решение по пилоту.
- После подтверждения бот спрашивает клиентку, напомнить ли о следующей коррекции. Только при согласии он через 21 день (ламинирование 42) отправляет приглашение «Хочу записаться / Напомнить через неделю / Больше не напоминать».
- По понедельникам в 10:00 мастер получает отчёт за неделю.

**Команды мастера:** `/list`, `/clients`, `/report`, `/tz Europe/Kazan`, `/interval 21`, `/delN` (отменить запись N).
**Клиентка:** `/forget` удаляет её данные.
**Оператор пилота (ADMIN_TG_ID):** `/stats` показывает метрики по каждому мастеру за 30 дней (неявки, подтверждения, подключение клиенток, согласия, приглашения). Сюда же приходят уведомления о новых мастерах и о сбоях рассылки.

Все события пишутся в таблицу `events`. Если мастер говорит «клиентке не пришло», там видно, что и когда было отправлено.

## Запуск

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Установите зависимости (нужен Python 3.11+):
   ```bash
   python3 -m venv .venv
   .venv/bin/pip install -r requirements.txt
   cp .env.example .env   # заполните BOT_TOKEN, MASTER_INVITE_CODE, ADMIN_TG_ID
   ```
3. Запустите:
   ```bash
   set -a; . ./.env; set +a
   .venv/bin/python -m korrekciya.bot
   ```
   В логе появится ссылка для мастеров: `https://t.me/<бот>?start=m_<код>`.

Тесты: `.venv/bin/pip install -r requirements-dev.txt && .venv/bin/python -m pytest`

### На сервере (VPS в РФ)

`/etc/systemd/system/korrekciya.service`:
```ini
[Unit]
Description=Korrekciya bot
After=network-online.target

[Service]
WorkingDirectory=/opt/korrekciya
EnvironmentFile=/opt/korrekciya/.env
ExecStart=/opt/korrekciya/.venv/bin/python -m korrekciya.bot
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```
Затем `systemctl enable --now korrekciya`.

Бэкап базы раз в сутки через cron: `sqlite3 /opt/korrekciya/korrekciya.db ".backup /backup/korrekciya-$(date +\%F).db"`. Хотя бы раз проверьте, что из бэкапа всё восстанавливается.

## Ограничения консьерж-версии (сознательно)

- **Нет своего расписания и свободных окон.** При «Перенести» бот передаёт просьбу мастеру, и новое время она согласует сама.
- **Голосовые сообщения не распознаются**, только текст.
- **Ответы на SMS бот не видит.** В SMS клиентку просят написать мастеру.
- **Один бот на всех мастеров.** Клиентка видит в сообщениях имя мастера.

## Перед первым платящим мастером

- [ ] Показать юристу схему «мастер — оператор ПДн, сервис — обработчик» и текст согласия (152-ФЗ). Подать уведомление в РКН.
- [ ] Разместить бота и базу на сервере в РФ.
- [ ] Для SMS: зарегистрировать имя отправителя в SMS.ru. Отправлять только сервисные сообщения.
- [ ] Настроить ежедневный бэкап и уведомления о сбоях (`ADMIN_TG_ID`).
